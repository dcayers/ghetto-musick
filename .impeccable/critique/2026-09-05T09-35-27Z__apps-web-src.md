## Design Specificity Verdict

Structurally category-interchangeable, locally authored. Identity lives inside 240x104px boxes and the lines between them. Shell is the Figma–Linear–Retool chassis (canvas-tools.tsx:40 cites Figma shortcuts by name). Palette is literal Tailwind stock. No font-family declared anywhere. Brand mark is a stock Lucide Waypoints glyph.

Authored and non-transferable: the transition edge's three-weight system; absence rendered honestly as a system-wide rule; the metric curve locked to lane geometry; Camelot-aware ordering refusing High/Low because 12A is adjacent to 1A.

Sharpest failure is self-inflicted: PRODUCT.md Principle 2 says the edge deserves the screen space list tools give tracks. The build gives the track a card, a row, a timeline block, and a four-section inspector; the transition gets a 1.5–4px stroke and an 11px label.

Deterministic scan: 3 findings, exit 2, all design-system-font-size, all true positives, zero false positives. text-[9px] below the DESIGN.md 10px floor at track-inspector.tsx:402, set-timeline.tsx:375, set-timeline.tsx:610. All other arbitrary sizes (10px x16, 11px x41, 12px x1, 13px x2) map exactly to the documented ramp.

SCOPE CAVEAT: the detector's 61 rules span only slop and quality. There is no accessibility category. Accessibility findings here are review-based and browser-measured, not machine-confirmed.

Visual overlays: none. The app never renders past its loading state, so injection into a working surface was impossible.

## Overall Impression

High craft colliding with low completeness. Reasoning in this codebase is better than most shipped products; nearly every non-obvious decision carries a correct comment naming the failure it prevents. Then you run it and the central verb is missing: you cannot create a transition. createTransition exists (graph-api.ts:130) and is imported nowhere while deleteTransition IS wired, so the graph is a one-way ratchet. The empty state instructs the user to do the one thing the app cannot do.

Biggest opportunity is not a redesign: close the loop, and make the machinery that already exists visible.

## What's Working

1. The transition edge is real design thinking. Alternatives thinned to 1.5px/45% and kept, not hidden; interactionWidth 18 keeps the thin stroke clickable; ", alternative route" appended to the accessible name. Selection is a halo, not a recolor, so the technique hue survives.
2. Honest absence applied as a system. NO_BARS = NaN; SourceDot renders nothing for null; energyDelta null rather than 0 because "±0" would read as "these match."
3. Three layout regimes chosen by behavior, not CSS (workspace-layout.tsx:102). Collapsed panels become a restore rail, not a zero-width column. Drawer state deliberately local.

## Priority Issues

### [P0] The product's defining object cannot be created
nodesConnectable={false} (graph-canvas.tsx:617); Connect/Link announce "not available yet"; createTransition imported nowhere though the endpoint exists. deleteTransition IS wired. Empty-state hint instructs "connect it to build a route."
Fix: wire createTransition to the handles that already render (theme.css:167 styles connecting/valid states nothing can reach), plus a keyboard route (select node, C, select second). Default technique "custom", bars null. Until then delete Connect/Link and rewrite the hint.
Command: /impeccable shape

### [P0] Every runtime error is invisible, and API-down hangs forever
announce() is the sole channel for ~15 failure paths, rendered sr-only. Verified: API down = 2 requests, both 502, indefinite "Loading workspace…". The "Could not load your graphs / Try again" branches are unreachable because the gate branches on isUnauthenticated (401) and a down API returns 502.
Fix: promote the status region to a visible transient surface (bottom-right, surface-overlay, hairline, auto-dismiss ~6s info / manual failure), keeping the sr-only mirror. Split announce() into announce()/announceFailure(). Add a non-401 error branch so transport failures reach a terminal state with retry.
Command: /impeccable harden

### [P1] The booth scene — the confirmed hard constraint — is entirely unserved
Independently agreed by token math and in-browser sampling:
- White on accent = 4.35:1, fails AA below 18px. 5 sites; two render at 9–10px. Ink token is worse (3.89).
- Input border #21212c on #0e0e14 = 1.21:1 vs WCAG 1.4.11's 3:1 for control boundaries.
- ink-subtle #6e6e80 = 3.49–3.85:1, carrying the 9px timeline axis and every section label.
- 60 of 98 type declarations are <=11px.
- Unfilled energy dots at 1.31:1, so "the dot count is the signal" fails visually.
Passing, for the record: focus rings measure 4.43:1 (B corrected its own false alarm); ink-muted on surface is 7.21:1.
Fix: lift --color-ink-subtle to ~#8a8a9c; add --color-accent-text ~#9b83ff for accent-on-dark text, keeping #7c5cff for fills; raise --color-border-strong to >=3:1. Then a booth density mode stepping the scale +2px as a :root class swap.
Command: /impeccable typeset

### [P1] Nothing is reversible
Undo/redo permanently disabled; no way to remove a node though removeNode exists (graph-api.ts:103); timeline remove X is opacity-0 until hover with no confirm and no undo. With the P0, the graph only accumulates nodes and only loses edges.
Fix, in cost order: (1) wire removeNode behind the inline two-step confirm the transition inspector already uses, making it the single destructive idiom; (2) add Undo to the new visible status surface (one-deep action stack, not a history system); (3) only then real undo/redo.
Command: /impeccable harden

### [P1] Emphasis spent on what doesn't exist, withheld from what matters
The loudest element is a bg-accent Play button toggling a local boolean (top-nav.tsx:241). Around it: Undo, Redo, Settings, Export, two dead tools, two dead views — ~1/3 of the top bar and 40% of the tool rail announcing absence. The transition gets less weight than a track's artwork thumbnail. Breaks the One Voice Rule: the app's most prominent violet is a transport control.
Fix: delete Play, Settings, the two dead tools, the two dead views. Give the accent fill to Export when it exists; put bar count and warning state on the edge label; add a persistent selected-edge readout in the empty top-center of the canvas.
Command: /impeccable distill

Sam (screen reader + keyboard): StarRating wraps five buttons inside role="img" (ui.tsx:224), making the subtree presentational — announces as a static image. Label reads "null of 5 stars" when unrated. Medium-width drawer has no role="dialog", no focus move, no trap; Tab walks the obscured page. Sam is the only user who learns when something fails.

Riley (stress tester): Saved pill lies reproducibly (change technique -> Unsaved -> drag node -> Saved -> reload -> change gone). Every inspector edit evaporates on selection change (local useState remounted by key={track.id}). Dropping a duplicate produces nothing visible.

Nia (booth, 8 bars left): set position is a 10px pill. Technique is an 11px chip; bar count and cue bindings are inspector-only. No full-screen, no dim, no "next up," no single action to hide library+inspector. The alternatives are the least visible thing on screen at 1.5px/45%.

## Minor Observations

1. Legend collides with itself (verified, one beyond A's report): #a3e635 = energy-3 + tx-filter; #fbbf24 = energy-4 + tx-energy + warn; #fb7185 = energy-5 + tx-cut; #38bdf8 = energy-1 + info. Violates DESIGN.md's Legend Rule. Cheap fix, systemic payoff.
2. InspectorSkeleton and Skeleton are dead code; isLoading defaults false and is never passed.
3. Library row's selected state is hue-only (1.13:1 tint); the comment describes a left bar not in the markup.
4. Two tooltip systems coexist (native title and RAC Tooltip) with different delays and keyboard behavior.
5. Technique picker is 11 flat options where every entry carries a family; five groups would halve the decision.
6. Waveform and DetailWaveform accept an energy prop and discard it (_energy), with four call sites passing it.
7. Serato import cannot be cancelled and reports nothing until it finishes; icon swaps to RefreshCw with no spin.

## Questions to Consider

1. PRODUCT.md says the edge deserves the screen space list tools give tracks. What does FlowGraph look like if the transition is the card on the canvas — carrying technique, bars, and cue bindings at readable size — and the track becomes the connector?
2. The palette is defended as a legend where every hue has one referent, yet it is Tailwind stock with four hues already doubled. Camelot has a color wheel these users already read without thinking. What is gained and lost by taking key color from the wheel already in the user's head?
3. Count what has no behavior: two tools, two views, Undo, Redo, Settings, Export, Play, Save, New Set, the transport. If you deleted every control that does nothing, would the workspace read as unfinished, or finally as focused?
4. The booth question is recorded undecided, but shipping a desk-only interface answers it. Using only state that already exists, what fits on one screen at arm's length — and which of these four panels is actually load-bearing?
